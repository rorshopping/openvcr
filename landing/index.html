Failed runs are unreproducible

Agents are non-deterministic. When a run breaks you can't replay it — you get to re-read logs and guess. Record the run once, replay it forever, byte for byte.

⎘

Agent tests are hand-mocked lies

Hand-written mocks don't match what the API really returns. Replay actual recorded traffic in pytest — deterministic, offline, and $0 per run.

⚠

Model updates break things silently

Providers update models under the same name. openvcr diff shows the exact per-request drift — so you upgrade on evidence, not hope.

How it works

One artifact — the cassette: a JSONL file of every request/response pair, streams included, secrets scrubbed.

  1. 1

    Record

    OpenVCR is a local proxy. Point your app at it — OpenAI SDK, Anthropic SDK, LangChain, curl, anything — and traffic passes through untouched while being teed to a cassette file.

    openvcr record \
  --upstream https://api.openai.com \
  --out agent.cassette.jsonl
  2. 2

    Replay

    The replay server answers from the cassette using exact request matching — including SSE streams re-emitted chunk by chunk. Same bytes, every time.

    openvcr replay agent.cassette.jsonl
# tests run offline, free, fast
  3. 3

    Diff

    Re-record after a model or prompt change. OpenVCR reassembles streams into text and tool calls, ignores provider noise, and shows you the real drift.

    openvcr diff baseline.cassette \
  agent.cassette # exit 1 on drift → CI gate

Questions, answered

How is this different from VCR.py / respx?

Those mock HTTP in Python only, from hand-written fixtures. OpenVCR records real traffic through a language-agnostic proxy, replays SSE streams faithfully, and diffs trajectories semantically — built for agents, where a "response" is a whole tool-calling loop.

Does it work with LangChain / LlamaIndex / the Vercel AI SDK?

Yes — anything that lets you set a base URL. That's every mainstream LLM library, in every language. No code changes, no plugins.

Where do my prompts and completions go?

Into a JSONL file on your disk. The core has no telemetry and makes no network calls beyond the API you point it at. Cloud upload is opt-in per cassette.

What if a test request doesn't match the cassette?

You get a 409 with the offending request's hash, what the cassette contains, and the exact command to re-record. Silent wrongness is the one thing OpenVCR refuses to do.
